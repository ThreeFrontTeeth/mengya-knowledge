# 知识库工作流

这是本库的操作手册，不是自动安装的 Agent Skill。首次整理样例见 [LLM Wiki](../06-Wiki/概念/LLM%20Wiki.md)；持续验证状态只在 [知识库使用验证](../01-进行中/知识库使用验证.md) 维护。授权边界统一遵循 [AGENTS.md](../AGENTS.md)，日期与资源位置统一遵循 [日期规范](../06-Wiki/资料进入与日期规范.md)。

## 整理资料

可以直接说：“把这份资料整理进知识库，优先更新已有主题，保留出处。”

1. 读取材料和来源说明，确认作者、原链接、日期、正文完整性、附件读取范围。遇到缺失，只处理能可靠读取的部分。
2. 按原链接及内容检查是否已收集，再查当天收集记录。已处理且无新内容的重复输入直接引用原结果，不创建副本，不制造更新时间。
3. 按 [分领域管理](../06-Wiki/分领域管理.md) 判断主要问题和领域，搜索已有领域入口、主题名、同义词及别名。领域来自实际内容，不固定为示例中的分类。列出本次新增、更新及跳过项，再在授权范围内执行。
4. 读相关旧页面，将新证据整合进对应段落。有独立阅读价值才另建来源摘要或分析；不要求一条输入生产多页。
5. 引用支持的具体结论，保留关键案例与条件。新来源改变旧判断时检查链接到该主题的分析、项目和成品；成品是否修订按其版本规则处理。
6. 验收后更新相关领域首页、知识首页、收集记录和日志。部分处理要列出缺失内容及已完成页面；不能提前标为已整理。

## 知识页怎么写

默认一页回答一个可长期复用的问题。新领域内容先按领域组织，概念、实体或分析子目录在有需要时再建；已有页面保持稳定路径。中文名称优先，常用英文词记录为 aliases。领域归属、跨领域引用及可选 domains 字段统一见 [分领域管理](../06-Wiki/分领域管理.md)。

元数据至少记录 created、updated、type、status、aliases。正文至少交代：核心结论、解释或案例、来源与适用边界。没有内容的小节不要保留占位文字。verified 只在实际核对时添加，并注明范围；不要求手填容易失真的来源数量。

建议的段落次序：先回答问题，再解释为什么，然后给必要案例，最后说明局限和关联。来源在对应段落就近放链接；可以另列证据表，但不能让读者猜每条来源支持哪句话。参考 [实际概念页](../06-Wiki/概念/LLM%20Wiki.md)，不用每次复制固定长模板。

冲突记录包含：争议点、旧依据、新依据、各自日期与条件、当前判断、还缺什么证据。这里只规定处理方式，不创建虚构冲突充数。

## 回答问题与沉淀

可以说：“根据知识库回答这个问题。”这默认只读。

需要保存时说：“把这次有价值的新理解补回相关知识页。”

先从知识索引定位相关领域和页面，必要时沿关联跨领域查找，再核实关键原文。回答尽量先用短结论，随后给证据和边界；库中不足则明确说明。是否查外部资料取决于问题与时效要求。

写回前判断新意：已有内容只链接；对旧结论有补充就更新原页；跨主题形成独立判断才新建分析页。不能把整段聊天记录当作知识，也不能把 AI 回答本身当作独立来源。本次写回样例见 [维护取舍](../06-Wiki/分析/萌芽知识库的维护取舍.md)。

## 检查知识库

可以说：“检查知识库，先报告问题。”默认只读；已授权修复的范围可以直接处理。

| 检查 | 怎么判断 | 不能夸大的结果 |
|---|---|---|
| 文件链接 | 链接目标存在，路径移动后引用同步；有锚点时核实标题 | 文件存在不代表章节或内容正确 |
| 孤立页面 | 知识页有索引入口；有意义的相关主题相互关联 | 不为凑连接数量乱加链接 |
| 领域归属 | 入口可达、名称一致；跨领域通过链接复用，同名概念核对含义 | 不把用户举例当作固定领域，也不强行归类 |
| 重复内容 | 比较标题、别名和所回答的问题 | 同名或文本相似仅是候选，不能自动合并 |
| 来源 | 关键事实有可定位出处，来源实际支持结论 | 有网址不等于有证据 |
| 冲突与时效 | 核对定义、条件、日期和相反证据 | 静态脚本不能判定所有事实真假 |
| 处理状态 | 已整理来源确有产物，部分处理有缺失说明 | “下载成功”不能算“整理完成” |
| 关联影响 | 旧判断变化后，检查引用它的分析和成品 | 链接正常不能保证关联结论已更新 |

完成一次资料处理后检查受影响范围；需要全库检查时由用户触发，不默认设置定时任务。输出具体文件、问题、依据、修复建议与未核实范围。遇到新问题再扩展检查，不做无意义反复扫描。

## 日志怎么记

沿用 [更新记录](../06-Wiki/更新记录.md)，新条目使用 `## [YYYY-MM-DD] ingest | 标题`，类型还可用 query、lint、maintain。记录来源或任务、改动页面、关键变化、验证结果和未完成项。旧日志不重写。

只有发生实际整理、写回或维护才追加持久日志。纯问答与无变化的重复检查不自动写日志。总首页最多展示近期几项重点，完整历史留在日志；知识首页为当前页面保留链接和一句说明。

## 从知识到创作

开始创作时先从 Wiki 找观点、案例与原始依据，在进行中形成草稿；确认完整后进入成品库。正文按口播节奏组织，但数字、引语和产品能力仍需核实。成品的来源与修订约定见 [成品入口](../02-成品库/成品入口.md)。
